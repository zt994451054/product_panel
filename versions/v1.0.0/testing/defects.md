## 缺陷状态流转

```
⏳ 待修复 → 🔄 修复中 → ✅ 已修复 → 🕐 待验收 → ✅ 验收通过（已关闭）
                                              ↘ ❌ 验收失败 → 返回「待修复」
🚫 豁免（任何级别，只能由使用者逐条明示；AI 不得自行豁免）
```

| 状态 | 说明 |
|------|------|
| ⏳ 待修复 | 缺陷已确认，等待研发修复 |
| 🔄 修复中 | AI 正在修复 |
| ✅ 已修复 | AI 已完成修复，触发人工验收 |
| 🕐 待验收 | 等待人工验收 |
| ✅ 验收通过 | 人工验收合格，缺陷关闭 |
| ❌ 验收失败 | 人工验收不合格，退回待修复 |
| 🚫 豁免 | 使用者逐条明示豁免（任何级别），原话记入本缺陷「豁免说明」，以及 test-report.md「豁免登记」（测试阶段）或 decisions.md 和 acceptance.md「遗留问题说明」（生产业务验证、生产验收阶段）；P0 缺陷豁免前 AI 须向使用者说明风险 |

## 说明

- **新增缺陷**：「缺陷列表」新增一行，详情区追加章节；关联用例在 test-cases.md「用例总览」改为 ❌ 失败
- **修复更新**（AI）：在「修复历程」节追加记录，「缺陷列表」状态改为 ✅ 已修复 → 🕐 待验收；填「是否改变原有约定」
- **验收更新**（人工）：只改「缺陷列表」验收状态
- **关闭前**：「是否改变原有约定」为「是」的，回写完成才能关闭
- **工件上传**：截图/录屏/日志按 SOP-10 上传 OSS（路径 `versions/{ver}/testing/`，命名 `YYYYMMDD-BUG{序号}-描述.ext`，见 OSS.md），CDN URL 填入「工件 URL」字段
- **hotfix 场景**：已发布版本的生产缺陷记在 `foundation/product/production-bugs.md`（PROD 编号），不改已发布版本的本文件；热修复版本自己的 defects.md 只记它在测试和发布中发现的缺陷（SOP-11）
- **豁免**：任何级别的缺陷都只能由使用者逐条豁免；未豁免的缺陷必须本版本关闭，测试才能放行
- **原型还原偏差**：与原型不一致即记为缺陷，不得自行认定为「视觉小问题」而不记录
- **修复影响接口/DB/需求**：推进到「已发布」时按[全量基线与版本增量](../../../agents/baselines.md)合入基线（SOP-07 / SOP-11）
- 变更追踪 → [CHANGES.md](../CHANGES.md)
