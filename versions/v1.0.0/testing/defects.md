## 缺陷状态说明

```
⏳ 待修复 → 🔄 修复中 → 🔍 待验收 → ✅ 验收通过（已关闭）
                                    ↘ ❌ 验收不通过 → 返回「待修复」
🚫 豁免（P1 缺陷经产品负责人确认）
```

| 状态 | 说明 |
|------|------|
| ⏳ 待修复 | 缺陷已确认，等待研发修复 |
| 🔄 修复中 | 研发正在修复 |
| 🔍 待验收 | 研发已完成修复，等待人工验收 |
| ✅ 验收通过 | 验收合格，缺陷关闭 |
| ❌ 验收不通过 | 验收不合格，退回重新修复 |
| 🚫 豁免 | P1 缺陷经产品负责人确认豁免 |

## 说明

- 缺陷编号格式：BUG-{三位序号}，如 BUG-001、BUG-002
- 发现缺陷时立即创建记录，同步将关联用例状态改为 ❌，在「关联缺陷」字段填写缺陷编号
- 修复完成后更新「修复记录」，状态改为 🔍 待验收
- **人工验收**：研发修复后须经人工执行关联用例或专项验证，验收合格后方可关闭
- 验收通过后更新「验收记录」，状态改为 ✅ 验收通过
- 验收不通过时追加新的「修复记录」，状态退回 ⏳ 待修复
- P1 缺陷豁免须产品负责人确认，填写「豁免说明」
- 统计表在每次状态变更后同步更新
- 修复若影响其他域文档，须通过 CHANGES.md 记录
→ 见 [CHANGES.md](../CHANGES.md)
