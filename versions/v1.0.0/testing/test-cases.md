## 说明

- **新增用例**：同步更新 ①「覆盖矩阵」；②「用例总览」表新增一行；③在「用例详情」区添加对应章节；类型、优先级保持一致
- **执行状态只按实际执行结果填写**：未实际执行的用例保持「⏳ 未执行」；使用者概括说「基本都过了」时，只把使用者明确点到的用例记为通过
- **执行更新**（AI）：「用例总览」改执行状态；详情区「执行记录」写最近执行时间、被测构建、实际结果和证据
- **验收更新**（人工）：只改「用例总览」验收状态；验收备注写在验收状态后面，如「✅ 验收通过（核对了文案和跳转）」
- **重新部署后**：按改动判断哪些已通过的用例受影响，受影响的退回 ♻️ 需回归；不受影响的在执行记录注明「构建 xxx 上的结果仍有效：理由」
- **执行失败附件**：失败截图/录屏按 SOP-10 上传 OSS（路径 `versions/{ver}/testing/`，命名 `YYYYMMDD-TC{序号}-描述.ext`，见 OSS.md），CDN URL 填入「工件 URL」字段
- **需求变更**（SOP-04）后：关联的 ✅ 通过 用例须退回 ♻️ 需回归，因为需求变了原测试结果可能失效，不退回等于伪装通过
- 变更追踪 → [CHANGES.md](../CHANGES.md)
