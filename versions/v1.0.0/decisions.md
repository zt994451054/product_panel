# v1.0.0 决策记录

> 本版本内使用者做出的决定：需求取舍、待确认问题的答复、暂定值、范围扩大、不测的项等。跨版本的技术选型仍写 `foundation/tech-arch/decisions/`（ADR）。

决定本身不写在本文档里。每条决定用 `node tools/panel.mjs decision add` 登记，拿到编号；用 `decision list --version {版本}` 查看。重新设计、改方案、改用例前，先运行 `decision list`，不违背仍有效的决定；要推翻就登记一条新的，带 `--replaces {旧编号}`。

**记录规则**（[AGENTS.md](../../AGENTS.md) §5.1）：
- 只记使用者明确说出的决定。`--quote` 只放他说的话，不改写、不补充、不截短；你的说明不放进原话
- 未答复、「你看着办」「你按规范来」不是决定，命令不记；问题留在原处继续待确认
- 「按建议」「可以」这类短话只对上一条消息里逐条列出的建议生效：每条建议登记一次，`--refers-to` 写明指的是哪一条
- `requirements.md`「待确认问题」有了答复，就登记一条，并在原问题后注明决定编号
- 需求、范围、验收标准类的决定由该版本登记的产品负责人做（见 `status` 输出），`--by` 写做决定的成员。不知道对话的是哪位成员时先问（[agents/state.md](../../agents/state.md) §4），问不到就不记
- 用例和缺陷的豁免记在 `testing/test-report.md`「豁免登记」和 `defect waive`，阶段签收用命令记录（SOP-07），不在这里重复；其余决定（含无人值守的预授权、生产验收中的遗留决定）都用 `decision add` 登记
