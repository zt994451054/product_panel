# 协作与交接

> 派子 agent、写外部系统、无人值守、交接、面板仓库的分支与提交，都按本页执行。红线摘要在 AGENTS.md §7。

---

## 1. 派发子 agent

子 agent 不继承你的上下文，也不会自动知道面板的红线。派发时写清楚：

```markdown
目标：要交付什么（文件、结论、清单），做到什么程度算完成
范围：只能读哪些路径、只能写哪些路径；明确不许碰的
红线：本任务涉及的禁止行为（如只读、不提交、不写外部系统、不改他人在用的文件）
资源：独占的资源（端口、测试账号、数据、外部配额）；与其他 agent 共用的资源怎么分
交付格式：结论在前，每条结论带证据位置；做不到的写明原因
```

- **共享台账只有一个写入者**：用例执行记录、缺陷表、状态表等，并行时由主 agent 汇总写入，子 agent 只交结果
- 子 agent 只说「正在等待」「已启动」就结束，不算交付。主 agent 要拿到结果或明确的失败原因
- 不派会互相影响的并行任务：同一个文件、同一个测试账号、全局进程操作（如按名字批量结束进程）、共享限额
- 子 agent 的结论由主 agent 核对后再写进面板，不直接当事实

## 2. 写入面板以外的系统

面板以外的系统指代码托管、CI/CD、云控制台、发布平台、工单、数据库、远程主机等。读取可以按任务需要进行；**写入**按以下五条：

1. **逐项授权**：每次写入前说明要改什么、改成什么、影响什么，使用者明确同意后才做。一次授权只覆盖说明过的那一项
2. **优先用 API 或命令行**：比在网页上点击更可核对；只能用界面时，事后截图或导出配置
3. **写后回读核对**：写完立即读回实际状态，与预期对比，差异报告给使用者
4. **检查工具默认值**：新建流水线、任务、规则时，工具可能自动加上触发器、通知、权限等默认配置。写之前确认，写之后核对，没有要求的就去掉
5. **被拦下不绕过**：遇到权限不足、安全拦截、审批要求，停下来告诉使用者，不换一种方式绕过去

写入的内容和结果记在对应文档：版本相关的写进 `versions/{ver}/CHANGES.md`，运维相关的同步 `engineering/docs/ops-profile.md`。

## 3. 无人值守连续推进

使用者说「你自己往下做」「我睡了你继续」时：

1. **先盘点决策**：列出接下来会遇到的决定，按三类分：
   - **范围**：做什么、不做什么。只能由使用者定
   - **操作授权**：写外部系统、部署、删除、提交合并等
   - **实现细节**：命名、结构、写法。可以由 AI 定，事后说明
2. **一次问完，拿到预授权**：范围和操作授权逐条问清，答案写进 `versions/{ver}/CHANGES.md`，注明授权人、时间、边界（如「只部署到测试环境」）
3. **标出需要人在场的步骤**：如扫码登录、短信验证码、物理设备、生产发布。无人值守时做到这一步就停，留下说明
4. **超出预授权的事不做**，记下来等使用者回来
5. **使用者回来时汇报**：做了什么、停在哪里、哪些等决定，按 [communication.md](./communication.md) 写

授权只记在 AI 私有记忆或对话里不算数，必须写进面板。

## 4. 交接

上下文压缩、换会话、交给别人接手时，留一份交接说明，20 行以内，复杂任务最多 40 行：

```markdown
当前任务：最新指令是什么；在做什么、停在哪
已确认事实：3–5 条，每条带证据等级
关键文件：仓库相对路径
工作区：在哪个分支、有没有未提交改动、改动属于哪个任务
下一步：1–3 条
不要做：暂停项、禁止事项、等待使用者决定的事
可以转交 / 不能转交：后台任务、会话内授权、临时环境会随会话消失，写明是否已失效
```

**证据等级**（汇报和交接都要标）：

| 等级 | 含义 | 例子 |
|------|------|------|
| 实测 | 本人执行并看到了结果 | 跑了命令、读回了配置、执行了用例 |
| 推断 | 根据材料推出来的，没有直接验证 | 「看配置应该是 docker 部署」 |
| 未验证 | 别人说的或计划中的 | 「@小王说已部署」「准备明天做」 |

**接手方先核对**：用 git 查看提交和未提交改动、读关键文件，对上交接说明再继续。「已完成」与文件实际情况不符时，以文件为准并告知使用者。

不要在交接里复制完整 SOP、需求、方案或长工具输出，给路径即可。交接说明与最新的使用者指令冲突时，以最新指令为准。

## 5. 面板仓库的分支与提交

- **不自动 stash，不自动切分支**。工作区可能有别人或别的会话的未提交改动，动之前先问
- 需要隔离时，从**最新的远端主线**切分支或建 worktree，不从落后的本地分支切
- 正式文档不引用未提交、未合入的内容；未提交的东西别人看不到，也可能丢失
- 提交前核对改动范围，只提交本任务的内容；不用 `git add .` 把别人的改动一起带走
- 新建根目录文件或顶层目录时同步 `.gitignore` 白名单（AGENTS.md §6）
- 版本关闭或任务结束后，清理为它建的分支和 worktree
- 长期分支只改自己范围内的文件；要改全局规则（AGENTS.md、`agents/`、`standards/`）时，单独提交合入主线，规则编号在合入时分配（见 [rules-log.md](./rules-log.md)）
