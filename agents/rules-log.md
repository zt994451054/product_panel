# 面板规则变更记录

记录本项目对面板规则的修改：AGENTS.md、`agents/` 下的文件，以及 `SETUP.md` 的配置项定义。产品规范（`standards/`）的修改不记在这里，在 `standards/README.md` 改状态即可；版本内的需求、方案变更记在 `versions/{ver}/CHANGES.md`。

## 规则

- **只有写进面板的才是规则**。对某个 AI 说过、存在 AI 私有记忆里的约定，要长期生效就记一条并改对应文件
- **编号在合入主线时分配**：在分支上写 `RULE-待定`，合入主线时按顺序编号，避免多条分支撞号
- **复盘的结论**以「规则候选」结尾，每条标「采纳」或「否决」及理由；采纳的在这里记一条并改规则，否决的留在复盘文档里

## 格式

```markdown
## RULE-{三位编号} | {YYYY-MM-DD} | {一句话标题}

**来源**：使用者的原话或决定（谁、什么时候），或复盘文档路径
**改动**：改了哪些文件、哪条规则，改前改后各一句
**影响**：对进行中的版本、其他分支有什么影响；没有写「无」
```

## RULE-待定 | 2026-11-25 | 确认要逐条、依据要核实；撞号和已发布版本的处理

**来源**：架构师 2026-11-25 的决定「其他按照你的建议来」（指上一条逐条列出的五条从严口径）；多人多分支并行与完整发布流程的实测
**改动**：
- `agents/communication.md` §3、§4，AGENTS.md §5.1、§7：笼统的话（「其余都通过」）不算逐条确认；「按建议」不延伸到上一条没列出的事；早先针对别的事说的话不挪用；一条消息里所有要使用者回答的都计入 4 个问题的上限
- SOP-07：门控条件的依据要核实过。只有口述、核实不了的记未通过；使用者明确决定按口述放行的，记决定后再记通过，并在签收摘要里单独列出
- `agents/state.md`：原话必须针对这件事；两人离线记了同一步不算矛盾；撞号后在后建一方的工作区里命令拒绝继续写，作废创建记录后它名下的记录一并失效；已发布的版本不能挂起、放弃、改期、回退，也不做在途确认；热修复版本号必须是补丁号，且要先有已发布版本或生产部署记录
- 需求条目和缺陷的状态改为用命令记录（2026-11-25，架构师「按照建议来」，指需求条目按功能级、复用事件机制、编号用成员标识加本人流水号、示例一并改）：`requirements.md` 去掉「需求状态」列，`defects.md` 去掉缺陷列表和状态列，只留叙述；SOP-01、03、04、05、07、12 相应改为 `item`、`defect` 命令；「需求分析」「测试」「发布」的门控由命令自动核对需求确认情况和缺陷关闭情况
- 全部登记类编号改为「前缀-成员标识-本人流水号」（`agents/state.md` §9）：需求条目、缺陷由命令分配，其余手工按同一规则取；模板和示例里的编号全部改成新格式
**影响**：进行中的版本要把已有的需求清单和缺陷用 `item add`、`defect open` 补登记一遍（补记用 `--at` 和 `--backfill`）；已有的旧编号可以继续用，新登记的按新规则

## RULE-待定 | 2026-11-20 | 状态改为只追加的事件记录，由命令读写；取消唯一主线

**来源**：架构师 2026-11-19 至 11-20 的决定：状态用入库的结构化数据做唯一来源；「如果有 2 个及以上版本在同时推进，就没办法以某个分支为准」；热修复「不用再去动原来已经封版和签收的版本」
**改动**：
- 新增 `agents/state.md`：状态怎么存、怎么读、怎么改，谁能决定什么，命令不能执行时怎么办
- AGENTS.md §0、§3：改前读 `SETUP.md` 状态表、`versions/CURRENT.md`、版本 README 阶段表；改后运行 `node tools/panel.mjs status`。§7 增加：不手写状态、不手改事件文件、不替使用者写原话、不自行改签收设置、版本多于一个时不自行挑版本
- SOP-07：改前「三处文件同步」，改后用命令记录进入阶段、门控核对、请求签收、签收；门控表改为按「要签收的阶段」列；签收按该阶段的签收设置，「测试」「发布」固定由人签
- SOP-06：改前先在主线登记占号、只有一个主线版本；改后多个版本地位相同，命令跨分支检查版本号
- SOP-11、`agents/baselines.md`：热修复是独立版本（五个阶段）；被修的已发布版本不改任何文档，修复版本只记在生产缺陷记录（解决了原先两条规则互相矛盾）
- SOP-00、00.6、01、03、05、08、09、09.5、12、`agents/collaboration.md`：读状态、记进展、确认配置项、记部署改为用命令；状态变更写完就提交并推送，删分支前先检查
- 新增只读驾驶舱：`node tools/panel.mjs render` 生成根目录的 `cockpit.html`（不入库），给人看；AI 读状态仍用 `status`
- 删除 `versions/CURRENT.md`、`versions/README.md` 的进度矩阵、版本 README 的阶段进度表和回灌记录、`SETUP.md` 的状态列
- 场景演练后补充（2026-11-20）：新增「当前操作者」（不入库的 `profile.md` + `whoami` 命令，`agents/state.md` §4），需要人决定的命令对不上成员就不记；读状态前先拉取；签收顺序固定为核对 → 请求 → 同意 → 记录；声明起点只用于存量产品、热修复只用于修生产缺陷；没有生产部署记录不能签收发布；推不了时只提交并照实说明
**影响**：进行中的版本需要把现有阶段和签收用命令补记一遍（`version new`、`version onboard` 或逐阶段带 `--at` 补记）；其他分支上手写的状态表合入后不再有效
