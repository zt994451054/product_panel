## 规则

1. **规划不是版本**：规划里的具体需求点先进需求池（[backlog.md](../product/backlog.md)，SOP-00.5，「备注」写规划材料链接），再按 SOP-01 纳入版本（新版本按 SOP-06 立项；补进在研版本按 SOP-04 登记范围变更）。不直接改版本文档。使用者说「规划里那个直接做」，也按这条走，并告诉使用者走到哪一步
2. **每份材料标状态**：讨论稿 / 候选 / 已定 / 已撤回。只有上面写的人明确同意才能标「已定」；AI 的建议、推导写成「建议」，不写成结论
3. **决定记在哪**：规划层面的决定按原话记在 discussion-log.md 当次记录的「定了的」；影响某个版本范围的，同时记入该版本 `decisions.md`
4. **日期是计划，不是承诺**：路线图上的时间写「计划」。路线图以 roadmap.md 为准；`versions/README.md`「版本规划」只放已定了版本号的，版本实际进度以 `versions/` 为准
5. **不改写旧结论**：方向变了，原材料标「已撤回」并写原因和替代它的材料；对外汇报过的材料标「已汇报 {日期}」，后续修改另起新稿
6. **入口保持最新**：新增、撤回、替代材料都同步下方「入口」表；新材料按主题放子目录，已有材料要移动先问使用者
