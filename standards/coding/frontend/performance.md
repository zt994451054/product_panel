# 前端性能规范

## 适用范围

- Web 前端项目（Vue/React/原生均适用）
- 新功能默认必须满足本规范，存量功能按迭代逐步收敛

---

## 性能预算（默认值，项目可覆盖）

【必须】以 Core Web Vitals 作为体验质量基线；有线上真实用户数据时按 P75 统计：

| 指标 | 目标阈值 |
|------|---------|
| LCP | ≤ 2.5s |
| INP | ≤ 200ms |
| CLS | ≤ 0.1 |

【推荐】首屏关键资源预算默认值：

- JS（首屏必须执行）gzip 后 ≤ 170KB
- 首屏图片总大小 ≤ 500KB
- 单张非装饰图片默认 ≤ 200KB（超出需有压缩说明）

【推荐】新增页面把 Lighthouse（移动端）自检写成测试用例可引用的检查项，默认值：

- Performance ≥ 80
- Accessibility ≥ 90
- Best Practices ≥ 90
- SEO ≥ 90

---

## 资源加载策略（必须）

【必须】路由级代码分割，禁止把所有业务页面打进单入口包。

【必须】首屏外图片使用懒加载；首屏主视觉图使用明确尺寸，避免布局抖动。

【必须】字体文件采用子集化与 `font-display: swap`，避免长时间不可见文本。

【必须】第三方脚本延后加载，不阻塞首屏渲染。

【推荐】高频复用静态资源接入 CDN，并设置合理缓存策略。

---

## 渲染与交互性能（必须）

【必须】列表渲染避免无界增长，长列表使用虚拟列表或分页。

【必须】高频事件（scroll、resize、input）进行节流/防抖处理。

【必须】防抖/节流策略按场景选择，避免误用：

- 输入联想、搜索建议、实时校验：优先防抖（defer 最后一次）
- 滚动监听、窗口缩放、拖拽跟随：优先节流（限制触发频率）
- 提交按钮与关键操作：必须防重复触发（按钮锁定/幂等保护）

【必须】避免在渲染路径执行重计算；复杂派生数据使用缓存（`computed`/memo）。

【必须】动画优先使用 `transform` 和 `opacity`，避免触发布局抖动属性。

【必须】减少强制同步布局与频繁回流/重绘：

- 避免在同一帧交替读写布局属性（如先读 `offsetHeight` 再写样式再读）
- DOM 批量更新合并到同一渲染节奏（可用 `requestAnimationFrame`）
- 避免频繁修改 `top/left/width/height` 等易触发布局计算的属性
- 复杂组件避免深层 DOM 级联样式联动，必要时拆分渲染边界

【必须】增量加载、图片异步加载、瀑布流/卡片流等中间态频繁变化场景，优先保留上一份稳定 UI 快照，禁止把未稳定结果直接反复渲染到页面造成闪烁、前跳或高度抖动。

【必须】图片失败、资源缺失、懒加载未就绪等失败态优先在进入可见 DOM 前判定，避免“先渲染占位/错误态再删除”的闪烁。

【必须】服务端渲染页面在 hydration 前后保持结构与关键样式稳定，禁止客户端在 hydration 初期立即改写关键布局或视觉层，造成真实闪烁、跳动或 mismatch。

---

## 全局机制与跨页面影响（必须）

【必须】新增页面或组件时，同时评估其对全局样式、全局脚本和共享状态的影响，禁止只在当前页面视角验证。

【必须】全局样式只承载 reset、design token、通用原子能力，禁止在全局作用域直接覆盖业务类名、标签样式或第三方组件默认样式。

【必须】页面样式默认局部生效，避免通过高优先级选择器、深层穿透或 `!important` 抢占其他页面样式。

【必须】共享布局容器（如 `body`、根节点、主内容区、滚动容器）上的样式改动必须评估以下影响：

- 是否改变其他页面的滚动行为、定位上下文或高度计算
- 是否影响已有吸顶、弹层、抽屉、浮标等组件层级关系
- 是否引入新的横向滚动、内容裁切或安全区错位

【必须】全局事件监听、定时器、观察器和外部脚本在页面卸载时完成清理，禁止把当前页面副作用残留到后续路由。

【必须】共享状态（全局 store、缓存、URL 参数、localStorage/sessionStorage）变更前明确作用域，禁止页面私有逻辑污染全局默认值。

【必须】路由切换区分“站内视图切换”和“真正离开页面/销毁组件”两类场景：前者不得盲目停止仍应继续的后台任务，后者必须完成停止、释放和恢复。

【必须】弹层、浮层、消息提示、全局 Loading 等覆盖层组件统一接入设计系统层级规范，禁止各页面私自定义 `z-index` 体系相互打架。

【必须】涉及滚动恢复的列表页按 `pathname + search` 等真实页面标识分桶存储位置，禁止多个筛选态、多个列表页或详情返回共享固定 scroll key。

【必须】列表滚动恢复、回填和自动补页逻辑要考虑页面高度晚到、图片晚到、分页数据晚到，恢复过程允许多次校正，禁止首次 clamp 后永久锁死位置。

【必须】同内容多实例并存（主视图、弹窗、分享预览、嵌入面板）时，DOM 查询、滚动测量、overflow 判断限定在当前组件实例作用域内，禁止直接依赖全局 `document.getElementById` 等跨实例查找。

【推荐】涉及全局机制的改动，把跨页面检查写成测试用例检查点：首页、列表页、详情页、弹层页、长滚动页各抽一类验证。

TypeScript 工程约束见 [JavaScript / TypeScript 编码规范](../languages/javascript-typescript.md)。
