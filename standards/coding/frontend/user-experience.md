# 前端用户体验实现规范

> 本页只定义前端实现底线。交互设计原则见 [UI/UX 设计规范](../../product/ui-ux-standards.md) 和 [桌面端 Web 交互规范](../../product/interaction/desktop-web.md)；UI 视觉细节以 [DESIGN.md](../../design/DESIGN.md) 为准，不在此重复定义色彩/字体等。

---

## 交互反馈（必须）

【必须】所有可点击元素在 Hover/Focus/Active 三种状态有明确反馈。

【必须】操作反馈时长按 UI/UX 设计规范实现；响应超过 300ms 必须出现加载态。

【必须】图标按钮的可点击范围可大于视觉图标本体，不得只按图标像素判定点击；热区下限见 UI/UX 设计规范。

【必须】操作结果可感知：

- 成功：明确成功提示与后续建议动作
- 失败：说明原因 + 可执行修复动作

【必须】Loading 反馈与操作范围一致：

- 页面首次加载：优先骨架屏或内容占位，避免整页空白
- 局部操作加载：只阻塞当前区域，避免全页一起转圈
- 提交类操作：按钮进入 Loading/禁用态，并保留原按钮文案语义

【必须】Loading 结束后状态明确：

- 成功：关闭 Loading，并展示结果或成功提示
- 失败：关闭 Loading，并立即给出错误原因与下一步操作
- 无数据：关闭 Loading 后进入空状态，不得一直停留在加载中

【必须】按钮、局部面板、页面级 Loading 各自表达的范围明确，禁止用户通过一个局部 Loading 或取消按钮误判“整个后台任务已经停止或完成”。

【必须】异步任务、局部刷新等场景在真实内容节点尚未插入前，允许补一个语义一致的临时 Loading 占位，避免界面短暂失去反馈。

【必须】禁止伪 Loading：

- 数据已失败但界面仍持续转圈
- 页面已可操作但覆盖层未消失
- 多个区域共用一个全局 Loading 导致用户无法判断具体哪里在加载

## 表单与错误提示（必须）

【必须】错误提示对用户友好，不直接暴露技术异常：

- ✅ “验证码已过期，请重新获取”
- ✅ “网络异常，请检查连接后重试”
- ❌ “Request failed with status code 500”
- ❌ “TypeError: Cannot read properties of undefined”

【必须】错误提示分层表达：

- 面向用户：说明发生了什么、会影响什么、下一步怎么做
- 面向研发：详细错误码、请求 ID、堆栈等进入日志或调试面板，不直接展示给普通用户

【推荐】错误提示附带可执行动作，如“重试”“返回上一页”“联系客服”“重新登录”。

【必须】实时校验与提交校验分层：

- 输入期：轻量规则（格式、必填）
- 提交期：完整规则（业务约束、冲突校验）

【必须】保留用户已输入内容，失败后不得整表清空。

---

## 容错与恢复（必须）

【必须】高风险操作（删除、支付、批量变更）提供二次确认，确认文案明确动作后果，禁止模糊确认框。

【必须】可逆操作优先支持撤销（Undo），而非仅弹确认框。

【必须】异常页面（404/500/网络失败）提供返回主路径或重试入口。

---

## 状态实现（必须）

【必须】核心页面覆盖四类状态：加载中、空状态、错误状态、无权限状态。

【必须】骨架屏优先于全局菊花转圈，降低等待焦虑。

【必须】错误状态区分类型，不同错误使用不同提示与动作：

- 网络异常：提示检查网络，并提供重试
- 权限异常：说明无权限原因，并提供申请或返回入口
- 数据不存在：说明对象不存在或已删除，并提供返回列表等兜底路径
- 系统异常：使用友好兜底文案，并保留问题上报入口

【必须】正文、卡片、列表等展示内容存在多个候选字段或多个加载阶段时，优先展示“当前最完整、最稳定、最符合用户理解”的结果，不得机械依赖单一字段导致正文缺失、内容倒退或展示截断。

---

## 行为一致性（必须）

【必须】同一个交互控件展示的状态含义前后一致。例如“取消”只表示取消当前前台等待时，不得让用户误解为已经终止后台任务。

【必须】同一套全局能力在不同页面行为一致，包括但不限于弹窗关闭方式、返回逻辑、Toast 位置、Loading 形式、错误提示样式。

【必须】切回旧页面、切换筛选、返回列表、恢复滚动等路径的体验与用户直觉一致：该回到原位置时不要落到底部，该回到顶部时不要保留旧筛选位置。

全局样式、监听器和共享状态不得影响其他页面，具体约束见 [前端性能规范](performance.md) 的「全局机制与跨页面影响」。

【推荐】涉及布局骨架、全局主题、路由守卫、滚动恢复、弹层容器的改动，把“进入页面 -> 操作 -> 离开页面 -> 返回旧页面”链路写成测试用例检查点。

---

## 可访问性底线（必须）

【必须】键盘可达：可交互元素支持 Tab 顺序访问。

【必须】焦点可见：不得移除焦点样式且无替代方案。

【必须】文本与背景对比度符合 WCAG 2.2 AA 最低要求。
