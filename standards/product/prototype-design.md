# 原型设计规范

> **主标准**：[Nielsen Norman Group - Prototyping](https://www.nngroup.com/articles/prototyping/)
> **副标准1**：[Atomic Design（Brad Frost）](https://atomicdesign.bradfrost.com/)（组件层级规范）
> **副标准2**：[Google Design Sprint](https://designsprintkit.withgoogle.com/)

---

## 原型保真度层级

| 层级 | 工具 | 目的 | 时机 |
|------|------|------|------|
| **低保真（Lo-Fi）** | 手绘、白板、纸质线框图 | 快速探索思路，验证信息架构 | 需求初期，发散阶段 |
| **中保真（Mid-Fi）** | 线框图、灰阶（工具不限） | 明确交互逻辑，对齐团队理解 | 需求确认后，开发前 |
| **高保真（Hi-Fi）与可交互原型** | 面板的统一原型工程（`foundation/design/prototype/`，Vite + React，按终端分路由）；使用 Figma 等设计工具时见下文「使用设计工具时的可选建议」 | 最终视觉方案和交互演示，用于开发交付与用户测试 | 交互确认后 |

面板默认把高保真和可交互合为一份：统一原型工程既是视觉稿，也能演示交互，版本差异记录在 `design-spec.md` 的「原型增量」节。

**原则：用最低成本验证最大的不确定性**

## Atomic Design 组件层级（Brad Frost）

```
原子（Atoms）→ 分子（Molecules）→ 组件（Organisms）→ 模板（Templates）→ 页面（Pages）
```

| 层级 | 说明 | 示例 |
|------|------|------|
| **原子** | 最小 UI 元素，不可再拆分 | 按钮、输入框、图标、颜色、字体 |
| **分子** | 原子的组合，有单一功能 | 搜索框（输入框 + 按钮）、表单项（标签 + 输入）|
| **组件** | 分子的组合，构成界面区块 | 导航栏、商品卡片、评论列表 |
| **模板** | 组件的布局框架，无真实内容 | 页面骨架，显示内容区域位置 |
| **页面** | 模板填入真实内容 | 最终页面效果 |

【推荐】设计系统和组件库按 Atomic Design 分层管理，统一组件命名。

## 原型交付规范

### 必要交付物

| 阶段 | 交付物 | 说明 |
|------|--------|------|
| 需求评审前 | 低保真线框图 | 覆盖核心流程，标注关键交互 |
| 研发启动前 | 统一原型中本版本涉及的页面（高保真、可交互） | 完整视觉，复杂交互的动效和过渡可在原型中直接演示；页面与需求模块的映射、还原优先级写入 `design-spec.md` |

### 标注规范

设计稿必须包含以下标注信息：

**尺寸与间距：**
- 间距默认参考 8pt 栅格系统（8, 16, 24, 32...），具体取值以 `standards/design/DESIGN.md` 为准
- 标注关键元素的宽高、padding、margin
- 响应式 Web 需说明断点（手机/平板/桌面）

**交互说明：**
- 点击/悬停/禁用等各状态
- 动效说明（时长、缓动函数）
- 错误状态和空状态

**内容规范：**
- 文本最大行数限制
- 图片比例和尺寸
- 字符数限制

## 响应式设计规范

视觉基线（栅格、字号、色值、断点）由各项目的 `standards/design/DESIGN.md` 定义；终端范围由 `requirements.md`「本版本交互终端」表决定。以下数值是默认参考值，与 DESIGN.md 冲突时以 DESIGN.md 为准。

【推荐】响应式 Web 的设计稿覆盖以下三种断点；只做单一终端（如仅桌面端）的版本不要求：

| 断点 | 宽度范围 | 设备 |
|------|---------|------|
| 移动端（Mobile）| < 768px | 手机 |
| 平板（Tablet）| 768px - 1280px | iPad、小屏笔记本 |
| 桌面（Desktop）| > 1280px | 电脑 |

**布局策略：**
- 以移动端为主的产品推荐移动端优先（Mobile First）设计，从小屏向大屏扩展；以桌面端为主的产品可从桌面端开始
- 使用相对单位（rem/em/%），而非固定像素
- 关键操作区域（按钮、输入框）在移动端高度 ≥ 44px（触摸目标最小尺寸，Apple HIG）

## 设计评审前检查清单

```
□ 覆盖了所有核心用户流程
□ 包含空状态（Empty State）：无数据时显示什么
□ 包含加载状态（Loading State）
□ 包含错误状态（Error State）
□ 覆盖了关键边界条件（最长文本、最多列表项）
□ 本版本迭代的终端均有设计
□ 组件与设计系统（DESIGN.md）保持一致
□ 交互逻辑有注释说明
□ 如有切图或图标资源，已命名规范（kebab-case）
```

## 桌面端 Web 交互补充

当原型面向桌面端 Web 产品，且包含复杂页面行为、搜索筛选、数据表格、弹窗/抽屉、卡片点击、CTA 层级或多状态反馈时，应参考 [桌面端 Web 交互规范](interaction/desktop-web.md)。

复杂桌面端原型至少应说明：

- 用户当前处于什么页面或状态
- 用户正在操作什么对象
- 主 CTA、次要动作和危险动作分别是什么
- 默认、加载、空、无结果、错误、权限等状态如何呈现
- 浏览器返回、前进、刷新和深链接是否需要保留状态
- 键盘用户如何完成主要任务

## 原型与研发交接

【必须】原型在研发开始前完成并通过设计评审；进入「技术方案」阶段前，须已在 `design-spec.md` 固定原型基准（SOP-07 阶段门控）

【必须】`design-spec.md` 固定本版本的「原型基准」（基准提交和原型路径），并写明「原型页面 ↔ 需求模块映射」和还原优先级；研发和测试只对照这一版原型

【必须】生成或修改任何页面前，先读取 `standards/design/DESIGN.md`

### 使用设计工具时的可选建议

团队在统一原型之外还使用 Figma 等设计工具时，以下组织方式仅为建议；设计工具中的稿件不替代统一原型，两者不一致时以 `design-spec.md` 固定的原型基准为准：

- 文件命名：`{项目名}-{功能名}-{版本}`，版本号用三段 SemVer（`vX.Y.Z`）
- 目录结构：设计系统 / 线框图 / 高保真稿（按终端分组）/ 可交互原型
