# UI/UX 设计规范

> **主标准1**：[WCAG 2.2（Web Content Accessibility Guidelines）](https://www.w3.org/TR/WCAG22/)（可访问性）
> **主标准2**：[Material Design 3](https://m3.material.io/)（通用 UI 设计原则，跨平台）
> **副标准**：[Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/)（iOS/macOS 原则）


> **优先级**：本页的字号、色值、间距等数值是默认参考值。项目的视觉基线以 [standards/design/DESIGN.md](../design/DESIGN.md) 为准，两者冲突时以 DESIGN.md 为准；可访问性要求（WCAG）是底线，DESIGN.md 不得低于它。

---

## 核心设计原则

1. **清晰（Clarity）**：界面目的明确，用户无需思考就能理解如何操作
2. **一致（Consistency）**：相似的功能使用相同的视觉语言和交互模式
3. **反馈（Feedback）**：每个操作都有即时、清晰的反馈
4. **容错（Forgiveness）**：提供撤销操作，错误信息帮助用户恢复
5. **可访问（Accessible）**：面向所有用户，包括有障碍的用户

## 可访问性规范（WCAG 2.2 AA 级）

【必须】所有新产品达到 WCAG 2.2 AA 级别。

### 颜色对比度

| 内容类型 | 最低对比度（AA）|
|---------|--------------|
| 普通文本（< 18pt）| **4.5:1** |
| 大文本（≥ 18pt 或 14pt 加粗）| **3:1** |
| UI 组件边框、图标 | **3:1** |

```
✅ 白色背景 (#FFFFFF) + 深灰文字 (#595959)：对比度 7.0:1
❌ 浅灰背景 (#E0E0E0) + 中灰文字 (#9E9E9E)：对比度 2.0:1
```

**工具**：[WebAIM Contrast Checker](https://webaim.org/resources/contrastchecker/)

### 触摸目标尺寸

【必须】可点击/可触摸区域最小尺寸：

| 平台 | 最小尺寸 |
|------|---------|
| 移动端（iOS/Android）| **44×44pt**（Apple HIG）；Material Design 建议 **48×48dp**，跨平台产品取较大值 |
| Web 桌面端 | **24×24px**（最小，WCAG 2.2 SC 2.5.8），推荐 **32×32px** |

### 键盘可访问性

【必须】所有交互元素可通过键盘操作（Tab 键导航）

【必须】焦点状态清晰可见（不得使用 `outline: none` 而不提供替代方案）

### 屏幕阅读器支持

【必须】图片提供 `alt` 文本（装饰性图片 `alt=""`）

【必须】表单输入框有对应的 `<label>`

【必须】图标按钮提供 `aria-label`：

```html
<!-- ✅ 正确：有语义标签 -->
<button aria-label="删除订单">
  <svg><!-- 垃圾桶图标 --></svg>
</button>

<!-- ❌ 错误：无语义，屏幕阅读器无法识别 -->
<button>
  <svg><!-- 垃圾桶图标 --></svg>
</button>
```

## 排版规范

### 字体层级

| 层级 | 用途 | 尺寸参考 |
|------|------|---------|
| Display | 大标题、Banner | 32-56px |
| Headline | 页面标题、卡片标题 | 24-32px |
| Title | 区块标题、弹窗标题 | 18-22px |
| Body | 正文内容 | 14-16px |
| Caption | 辅助说明、时间戳 | 12px |
| Label | 按钮文字、表单标签 | 12-14px |

【推荐】正文字号不小于 **14px**（行业惯例；WCAG 没有规定最小字号，但要求文字可放大到 200% 而不丢失内容）

【必须】行高（line-height）：正文 **1.5**，标题 **1.2-1.3**

### 字体选择

【推荐】使用系统字体栈，避免加载额外字体资源：

```css
/* 系统字体栈 */
font-family: -apple-system, BlinkMacSystemFont, "Segoe UI",
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
             sans-serif;
```

## 颜色规范

### 颜色角色（参考 Material Design 3）

| 角色 | 用途 |
|------|------|
| Primary | 主要操作、品牌色 |
| Secondary | 次要操作、辅助元素 |
| Error | 错误状态 |
| Surface | 卡片、对话框背景 |
| Background | 页面背景 |
| On Primary / On Surface | 主色/表面上的文字颜色 |

【必须】所有颜色在设计系统中定义为 Token，代码中通过变量引用，禁止写死色值

### 语义颜色

下表色值仅为示例（取自 Material Design 2 色板），实际色值以 DESIGN.md 的 Token 为准，且需满足对比度要求。

| 含义 | 颜色 |
|------|------|
| 成功 | 绿色系（如 #4CAF50）|
| 警告 | 橙色系（如 #FF9800）|
| 错误 | 红色系（如 #F44336）|
| 信息 | 蓝色系（如 #2196F3）|

## 间距规范

【必须】使用 **8pt 栅格系统**，间距以 8 的倍数为主，4px 作为半步仅用于极小间距：

```
4px  → 极小间距（图标与文字间）
8px  → 小间距（列表项内部）
16px → 标准间距（卡片内边距）
24px → 中等间距（模块间距）
32px → 大间距（页面区块间）
48px → 特大间距（页面顶部、底部）
```

## 交互反馈规范

### 状态定义

每个可交互元素必须设计以下状态：

| 状态 | 触发条件 | 视觉变化 |
|------|---------|---------|
| Default | 默认 | 标准样式 |
| Hover | 鼠标悬停（Web）| 轻微变暗/变亮，颜色加深 8-12% |
| Focused | 键盘 Tab 聚焦 | 明显的焦点轮廓（不得省略）|
| Active/Pressed | 点击按下 | 明显压下效果，颜色加深 16-20% |
| Disabled | 不可用 | 透明度降低至 38%，不响应交互 |
| Loading | 操作处理中 | 加载指示器，防止重复提交 |

### 操作反馈时长

| 操作类型 | 反馈时长 |
|---------|---------|
| 即时操作（按钮点击）| < 100ms 视觉响应 |
| 短操作（表单提交）| 显示 Loading，≤ 2s 完成 |
| 长操作（文件上传）| 显示进度条 + 预估时间 |
| 异步通知 | Toast/Snackbar，3-5s 自动消失 |

## 空状态设计

【必须】所有列表/内容区域必须设计空状态：

| 空状态类型 | 元素 |
|-----------|------|
| 无数据 | 插图 + 说明文字 + 引导操作按钮 |
| 搜索无结果 | 说明搜索词 + 建议操作 |
| 网络错误 | 错误说明 + 重试按钮 |
| 无权限 | 说明原因 + 申请权限入口 |

## 表单设计规范

【必须】输入框标签（Label）始终可见，不使用 placeholder 替代 label

【必须】错误信息显示在输入框下方，文字说明具体原因：

```
✅ "手机号格式不正确，请输入 11 位数字"
❌ "格式错误"
```

【必须】必填字段标注 `*`，并在表单顶部说明 `* 为必填项`

【推荐】实时校验（用户离开输入框时），而非仅在提交时校验

## 桌面端 Web 交互细分补充

本规范定义通用 UI/UX 基础原则。当任务涉及桌面端 Web 产品的页面行为、组件选择、状态反馈、搜索筛选、数据表格、CTA 层级、弹窗/抽屉、浏览器返回前进、键盘可访问性时，应进一步参考 [桌面端 Web 交互规范](interaction/desktop-web.md)。

两者同时适用时，本规范负责基础可访问性、排版、颜色、间距和通用控件要求；桌面端 Web 交互规范负责更具体的交互行为和验收检查。
