# 测试规范

> 本规范优先于公司级规范，未覆盖条目以公司级规范为准。

## 测试分层

| 层级 | 说明 | 覆盖率目标 |
|------|------|----------|
| 单元测试 | 函数/模块级别，由研发编写，在工程仓库中维护 | ≥ 80% |
| 集成测试 | API/服务间协作，自动化，每次 CI 触发 | 核心链路 100% |
| E2E 测试 | 完整用户流程，staging 环境触发 | 主流程 100% |
| 性能测试 | 压测/负载，版本发布前执行 | 按版本定义 |

## 用例规范

- 测试用例统一记录在 `versions/{ver}/testing/test-cases.md` 单文件中，用例编号格式：`TC-{三位序号}`
- 每个用例必须包含：前置条件、操作步骤、测试数据、预期结果、优先级；预期结果须可直接判定且只有一种正确结果（具体文案、数值、状态码、跳转），不得写「显示正常」「符合预期」「返回 4xx」
- 用例覆盖本版本全部新特性点和对已有功能逻辑、UI 的全部改动点，用 test-cases.md「覆盖矩阵」逐项对照
- UI 用例引用原型路由、还原优先级和原型基准；还原偏差记为缺陷
- P0 主流程用例按生产默认配置执行
- 优先级定义：P0 阻断发布 / P1 严重影响功能 / P2 一般 / P3 轻微

## 缺陷规范

- 严重级别：P0（阻断）/ P1（严重）/ P2（一般）/ P3（轻微）
- 缺陷状态流转：⏳ 待修复 → 🔄 修复中 → ✅ 已修复 → 🕐 待验收 → ✅ 验收通过 / ❌ 验收失败

## 发布门禁

- 全部用例执行并通过、全部缺陷关闭，才能推进到发布；未通过项只能由使用者逐条豁免并登记（AGENTS.md SOP-03 测试底线与豁免规则）
- 测试结论只有「通过」和「不通过」
- 具体退出条件见 versions/{ver}/testing/test-plan.md「退出条件」，各版本不得放宽
