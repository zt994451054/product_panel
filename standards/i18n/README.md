# 多语言（i18n）规范

> 🧩 **可选模块**。在 `SETUP.md`「可选模块」表中启用后才生效；未启用时 AI 不读本文件。
> 适用范围：所有用户可见文案，包括原型、各端前端、后端返回给用户的提示和邮件、通知。

---

## 启用时要做

使用者同意启用后，AI 和使用者一起填好下面的「项目填写」各节，不确定的标「待确认」：

- [ ] 语言范围（开放的、储备的、默认语言、缺译文时回落到哪种语言）
- [ ] 文案母版放在哪、格式、key 怎么定
- [ ] 各端副本在哪、用什么同步（脚本或人工）
- [ ] 术语表、禁用词表（目标市场有要求时）
- [ ] 当前版本 `requirements.md` 写明本版本的语言范围；已有文案还没进母版的，列为待办

---

## 一、底线（启用后必须遵守）

1. **文案只有一份母版**。母版是所有译文的唯一来源，只改母版；各端（原型、Web、App、桌面、后端）用的是从母版同步出来的副本，**不手改副本**。没有同步脚本时，人工同步也以母版为准，并在提交前逐项核对
2. **key 规则只用一种**，写在下方「项目填写」，新文案照做
3. **动态内容用插值，不拼字符串**：`t('共 {{count}} 条', { count })`，不写 `t('共') + count + t('条')`，不同语言语序不同
4. **提交前核对母版与副本一致**；有校验脚本就跑，没有就逐项比对。缺译文的条目列出来，不静默回落
5. **术语统一**：术语表里有的词按表翻译，不各自发挥；新出现的核心词先加进术语表再用
6. **整理文案、翻译不等于改代码**：使用者只要求扫描、分析或翻译文案时，产出写在文档或表格里；改源码、改母版要使用者明确说

## 三、启用后的附加要求

| 环节 | 要求 |
|------|------|
| 需求（SOP-01） | `requirements.md` 写明本版本开放的语言；新增功能的用户可见文案要求进母版 |
| 产品设计 | 原型文案从母版取；按最长的开放语言检查布局（换行、截断、按钮宽度） |
| 技术方案（SOP-02） | 写明新文案的 key、后端返回给用户的文案怎么本地化、日期 / 数字 / 货币格式 |
| 测试设计（SOP-03） | 每种开放语言至少覆盖核心路径的界面检查；覆盖矩阵有「缺译文、回落」的检查行 |
| 开发与提测 | 提测前母版与副本一致性核对通过，结果写进提测说明 |
| 变更（SOP-04） | 新增开放语言、改默认语言属于范围变更，按 SOP-04 登记 |
