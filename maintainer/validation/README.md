# 面板验证套件

回答四个问题：优化做了没有、哪些流程改善了、哪些必做的流程没做、还有哪些缺陷。做法是先对优化前的模板跑一次**基线**，之后每期改动后用同一套检查重跑，对比结果。

## 三层验证

| 层 | 验证什么 | 入口 | 成本 |
|---|---|---|---|
| L1 静态检查 | 结构是否正确：SOP 引用、入口一致、绝对路径、凭据、链接、白名单吞文件、阶段一致、测试放行规则、规范索引 | `node maintainer/validation/check.mjs` | 秒级，每次提交可跑 |
| L2 场景演练 | 流程是否被执行：新 AI 在沙箱里按预设消息工作，另一个 AI 按清单评分 | [scenarios/](./scenarios/README.md) | 每个场景一次子 agent 演练 + 一次评审 |
| L3 历史回放 | 能否挡住真实发生过的问题：逐条判断面板规则能否预防 | [replay/cases.md](./replay/cases.md) | 一次文档评审 |

## 目录

| 路径 | 内容 |
|---|---|
| `check.mjs` | L1 静态检查脚本，FAIL 时退出码为 1 |
| `scenarios/` | 6 个场景定义（使用者消息、预设回答、评分清单）与沙箱准备脚本 `prepare.mjs` |
| `fixtures/` | 场景夹具：`seed-v1/`（BookEasy v1.0.0 技术方案已完成）、`legacy-shop/`（合成存量工程，含凭据陷阱与矛盾文档） |
| `replay/cases.md` | 43 条历史回放用例（已去除项目与业务细节） |
| `tracker.md` | 优化项追踪矩阵：每个优化项的验收标准与对应检查 |
| `reports/` | 基线与每期对比报告 |

## 节奏

- 每期 PR：跑 L1，并跑与本期相关的 L2 场景作为回归。
- 全部完成后：L1–L3 全量重跑，出最终对比报告。
- AI 行为不完全确定：关键场景跑两次，两次结论不一致记为缺陷（说明规则不够确定）。

## 局限

- 只在 Claude Code 上演练；Cursor / Windsurf 入口只做静态一致性检查。
- 模拟使用者不等于真实使用者，最终需要一次真实项目试点确认。
- 视觉还原只验证流程（用例与退出条件是否覆盖），不做真实视觉比对。
