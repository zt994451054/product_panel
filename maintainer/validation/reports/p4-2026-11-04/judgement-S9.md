## 4. 面板缺陷（执行 agent 的失误或临场处理中，由规则缺失或矛盾导致的）

### 中

**缺陷 1：只定义了「已发布」和「生产验收中」，没定义「已签收但因例外上线未标已发布、也没打 tag」的版本出了线上缺陷怎么办**
- 位置：agents/sop/SOP-00.6-production-bugs.md:16–18（只区分已发布 / 生产验收中）；agents/sop/SOP-11-hotfix.md:3、6（触发条件限「已发布」版本，要从发布 tag 拉分支）
- 表现：第 5 轮 v1.0.0 已交付签收、真实用户在用，但没标「已发布」、也没打 tag。agent 自己判断走生产缺陷池（production-bugs.md:46 发现版本一栏写了一长串说明），热修复的前提「从发布 tag 拉分支」无法满足，只能提醒先打 tag。
- 建议：SOP-00.6 第一步加一条：「交付已签收、真实用户在用，但因例外上线或收尾未完成而没标『已发布』的版本，视同已发布，走生产缺陷池」；SOP-11 第 1 步加：「被修版本还没打 tag 时，先完成收尾清单的『合并与标记』，或从线上 `/version` 对应的提交拉分支，并在热修复 README 里写明」。

**缺陷 2：回灌只写在热修复 SOP 里；处理策略选 B/C 或还没决定时，没规定要不要排查在途版本、结论写在哪**
- 位置：agents/sop/SOP-11-hotfix.md:21–25（回灌记录在 v1.0.1/README.md）；agents/sop/SOP-00.6-production-bugs.md:30–38（第三、四步不涉及在途版本）；foundation/product/production-bugs.md 模板（没有「影响的在途版本 / 回灌」字段）
- 表现：第 5 轮策略未定，agent 把回灌计划临时写进 PROD-001 新加的「影响的在途版本」段（production-bugs.md:75），评分要求的「回灌记录」无处可写。
- 建议：production-bugs.md 模板的详情加「影响的在途版本（逐版本：有无同样缺陷 / 处理 / 复现用例）」字段；SOP-00.6 第三步要求登记时就逐个核对在途版本，不管选哪种策略；SOP-11 第 7 步改成「从 PROD 条目带入并补全到 v1.0.1 回灌记录」。

**缺陷 3：止血本身要改代码并发生产时，没有规定怎么记录、要过哪些检查**
- 位置：agents/sop/SOP-11-hotfix.md:12（止血选项列的是回滚、开关、限流、公告）；SOP-11.md:38 的示例把「Safari 上显示提示」写成「需要改配置」，回避了要发版的情况
- 表现：第 5 轮使用者选的提示需要改 booking-web 并发生产。agent 只能写「记进后续修复版本的发布记录」（production-bugs.md:73）；策略选 B/C 时，这次生产发布没有任何发布记录，相当于没登记的例外上线。止血选项也没写代价（S9-07 ⚠️）。
- 建议：SOP-11 第 0 步加两条。①每个选项写明代价，以及要不要发新制品。②要发新制品的止血，在 PROD 条目的「止血」段记下制品号、staging 验证结果、生产业务验证和线上版本标识核对；如果后面开了热修复版本，同步到它的 release.md「例外上线」。同时把示例改成真正不用发版的方式（如配置开关），或者在示例里写明要发版。
