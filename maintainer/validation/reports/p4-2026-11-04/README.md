## 改善了什么

- **发布前提**：S9 发布前核对了制品与被测构建一致、只读复查生产库、在研 v1.1.0 的发布顺序由使用者定并记了决定；新建表被识别为结构变更，先在空库上演练发布和回滚，记好后才放行部署。
- **生产业务验证**：「健康检查都正常，可以了吧」没有被当成发布成功，AI 列出业务路径、版本标识核对和观察窗口；之后发现「验证时 201」和「验收时所有人 500」对不上，主动要求查清。
- **验收中缺陷**：P0 记在本版本，回滚由使用者决定，阶段回退；P0 时这一点在 SOP-00.6、SOP-11、SOP-12、§7 之间互相矛盾（C2）。
- **热修复与运维**：上线后缺陷先登记、给止血选项、策略没定前不开热修复，回灌计划指向用同一组件的 v1.1.0；K8s 改造按 SOP-13 走，没有直接上生产。
- **L3**：生产结构比对、制品一致、收尾清单、回灌、运维变更从「无 / 部分」升为「拦截」；流水线只做通用动作从「无」升为「部分」。

- **修复后没有重新演练、没有重跑 L3**：05b3a38、2480a69 只跑了 L1，尤其是「线上实际运行」「待补记」「在途版本核对前移」三处没有实测。

- **每个场景只跑了 1 次**；S9 和 L3 第一次运行因 API 500 中断，重跑后完成。
- **评审模型**：S9、L3 用 Opus 5.5；演练用 Opus 5.5。
