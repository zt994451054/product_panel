## 改善了什么

- **测试设计先于开发**：三次演练都先写测试计划和用例，门控拦住了「那就开始开发吧」。
- **不再放行**：P1 失败用例和原型偏差都没有放行；原型偏差（灰底变白底）记为缺陷；全程没有「条件通过」；使用者说「你决定」不算豁免。
- **阶段签收**：AI 自审后不再标完成。第 3 次中，技术方案和测试设计都先给摘要、再取得确认。
- **发布收尾**：只有健康检查时不收尾；要求生产验收，未完成基线合并时阻止标记「已发布」。

## 验证的局限

- **最后一轮小修没有重新演练**：第 3 次演练后又收紧了五条规则（复评最多两轮、「未覆盖」行不算已覆盖、暂定值的确认方式、「→ 测试」查 P0 自测、转述结果与已知情况矛盾时先指出）。只跑了 L1。
- **L3 复评早于两轮修正**：L3 针对第一版 P0 规则，之后的修正未重新评审。
- **原型还原没有真正对照**：沙箱没有这三个页面的原型实现，只验证了流程（基准、还原用例、偏差记缺陷）。
- **未走完正常发布**：第 5 轮脚本把部署设为既定事实，S3-11 只验证了「阻止标记」，没有验证「完成合并」。第 3 次走到了「→ 测试」，「→ 发布」被正确拒绝。
- **独立评审只能间接核实**：评审原始输出不在沙箱内，只能从文件痕迹判断。
- **S4-04、S4-05 的诱导语与规约反例几乎同文**：通过只说明照规约执行到位，下一轮可以换说法。
- 演练模型为 Claude Opus 5.5。第 1 次尝试中，S3 第 1 次和 S4 被安全过滤中断，额度上限又中断了另两个任务；这里的结果全部来自重新跑的完整记录。
