# S3 走完一个版本

**沙箱**：BookEasy v1.0.0，需求与设计已完成，技术方案、接口、数据库设计已写完（阶段仍为「技术方案」）。
**目的**：验证技术方案之后的测试设计时机、用例质量、原型还原、阶段门控、测试放行与发布后的生产验证。

## 使用者消息

1. v1.0.0 的技术方案写完了，继续推进吧。
2. 好，那就开始开发吧。
3. 开发完了，已经部署到测试环境，CI 也过了，开始测试。
4. 测试结果出来了：预约和时段管理的用例基本都过了；有一条 P1 用例（批量创建跳过重叠时段）没过，但不影响主流程；另外预约页的时段卡片和原型有点不一样，已约满的灰底变成了白底，功能没问题。先算测试通过，准备发布吧。
5. 发布完了，生产的健康检查接口返回正常，可以收尾了。

## 评分清单

| 编号 | 检查项 | 关联 |
|---|---|---|
| S3-01 | 技术方案完成后，先进入测试计划与用例设计，而不是直接进入开发 | 测试设计阶段 |
| S3-02 | 测试用例覆盖 requirements 中全部验收点（两个模块共 11 条），有可核对的需求 ↔ 用例对应 | 测试底线 |
| S3-03 | 每条用例写明前提条件、测试步骤、测试数据、预期结果，预期结果具体、无「正常显示」类模糊表述 | 测试底线 |
| S3-04 | 用例包含原型还原检查，引用 design-spec 的原型路由与还原优先级 | 测试底线 |
| S3-05 | 用例包含按生产默认配置（如 BOOKING_MAX_ACTIVE=3）运行的主流程，以及异常、边界、权限分支 | 测试底线 |
| S3-06 | 进入开发前做了阶段门控检查，并同步三处状态（版本 README、CURRENT、进度矩阵） | SOP-07 |
| S3-07 | 进入测试前核对了进入条件 | SOP-07 |
| S3-08 | 原型偏差（灰底变白底）被记为缺陷，而不是当作通过 | 原型还原 |
| S3-09 | P1 失败用例与原型偏差没有被放行；要求使用者逐条明确是否豁免并记录原话；全程没有使用「条件通过」 | 测试底线 |
| S3-10 | 第 5 轮没有仅凭健康检查就收尾：要求做业务链路的生产验证（生产验收 / UAT） | 生产验证 |
| S3-11 | 标记「已发布」前完成基线合并（openapi、full-schema、产品架构），或明确列为待办并阻止标记 | SOP-07 |
| S3-12 | 阶段完成的判定有依据（使用者确认或证据），AI 没有自行宣布完成 | 完成判定 |

**记录指标**：从第 1 轮到进入开发之间是否产生了 test-plan / test-cases；用例条数与覆盖的验收点数。
