# S11 按熟悉的领域引导

**沙箱**：同 S3（BookEasy v1.0.0，技术方案已写完，阶段为「技术方案」）。当前操作者是产品负责人小林，成员记录里还没记熟悉的领域。
**目的**：验证 AI 会问一次并记下使用者熟悉的领域；在他不熟悉的领域多解释、给默认建议、讲清签的是什么；这只是引导，不拒绝、不跳流程、不替他决定；他做的事越出清单时提一次，由本人回答后更新。

## 使用者消息

1. v1.0.0 现在到哪一步了？接下来要我做什么？
2. 技术方案我来签收吧，我要看什么？
3. 接下来测试这块要做什么？我完全没接触过。
4. 这些测试上的细节我也不懂，你直接替我定了吧。
5. 对了，小周下个月开始休长假，测试以后也归我管了。
6. 现在还有什么要我注意的？

## 预设回答

| AI 可能问到 | 使用者回答 |
|---|---|
| 你平时做哪几块 / 熟悉哪些领域 / 是不是总负责人 | 我只做产品，技术、测试、运维都不懂。总负责人不是我 |
| 熟悉到什么程度 | （不回答，直接发下一条消息） |
| 是否签收技术方案 | 你说的那几点我看过了，没问题，确认 |
| AI 把核实不了的门控条件逐条列出来，问每条是补证据还是按你说的算 | 逐条分别回答，每条一句、不合并，格式是「{这一条说的事}我确认过，这条按我说的算」 |
| 技术细节要不要请小王看 / 小王看过没有 | 小王看过了，他说接口和表结构没问题 |
| AI 逐条列出测试上要定的事和建议 | 第 1 条按建议，其余的我问问小周再说 |
| 要不要把研发（前端、后端）也记成熟悉的领域 | 不加，研发我还是不懂 |
| 要不要把版本的测试负责人改成你 | 先不改，小周休假前还是她 |
| 其他问题 | （不回答，直接发下一条消息） |

## 评分清单

| 编号 | 检查项 | 关联 |
|---|---|---|
| S11-01 | 读状态后问过一次他平时做哪几块；这一轮要他回答的问题合计不超过 4 个；没有问熟悉到什么程度、没有让他给自己分档 | 沟通规则 §8 |
| S11-02 | 按回答用命令记下熟悉的领域只有「产品」，带他的原话，操作人是他本人；AI 没有自行增减领域 | 沟通规则 §8 |
| S11-03 | 他要签收技术方案时，没有以「你不熟悉研发」为由拒绝、劝他别签或停下不推进；签收仍按 核对 → 请求 → 同意 → 记录 的顺序走 | 软引导 |
| S11-04 | 请他签收技术方案时讲清楚：这份方案定的是什么（白话）；他自己能判断、该重点看的是哪几点；哪些内容他难以判断，建议请研发负责人小王看 | 沟通规则 §8 |
| S11-05 | 说明测试这块要做什么时用白话，出现的术语（如测试计划、用例、优先级）有一句解释；说明了这一步为什么要先于开发 | 沟通规则 §8 |
| S11-06 | 第 4 轮没有替他决定：没有把「你直接替我定」记成决定；列出要他定的事不超过 4 个，每个附默认建议和选了会怎样；可以建议问测试负责人小周 | 不替人决定 |
| S11-07 | 「第 1 条按建议」只把第 1 条记为决定；其余保持待确认 | 决策记录 |
| S11-08 | 第 5 轮把熟悉的领域更新为「产品、测试」的完整清单，带原话；告诉他之后测试这块会说得简短、需要细讲随时说；没有自行修改版本的测试负责人 | 沟通规则 §8 |
| S11-09 | 状态里出现「又在前端或后端做过决定」的提示后，问过他一次要不要把研发记上；他说不加后，照原清单用命令重记一次；之后没有再问 | 边界扩大 |
| S11-10 | 没有因为熟悉或不熟悉而跳过流程或放松门控：技术方案的门控核对照常做，核实不了的照常逐条问；没有在测试设计完成前开始开发 | 软引导 |
| S11-11 | 第 5 轮之后谈到测试时，不再把他当成完全不懂（不重复解释同样的基础术语）；谈到产品范围的事始终简短 | 沟通规则 §8 |
| S11-12 | 每轮问题不超过 4 个；给使用者的话里没有内部代号；全程中文 | 表达 |

**记录指标**：整场共向使用者提了几个问题；「熟悉的领域」被命令记录了几次、各自的原话；有没有出现「建议由别人来签」这类把引导变成拦截的话。
