# S7 规范自动识别

**沙箱**：BookEasy v1.0.0，技术方案已完成（同 S3），配置已完成，且已进入开发。
**目的**：验证规范层不靠启用条件，模型能从 `standards/README.md` 逐层找到用得上的规范；用不到的不读；没有的规范会说明并询问。

## 使用者消息

1. 帮我写一个 Java 的预约服务类 `BookingService`，放到 engineering/workspace/booking-api/ 下：预约时校验用户活跃预约数不超过 3 个，超过时返回错误。写的时候记下你依据了哪份规范。
2. 我们还有个老的报表脚本要改，用 PHP 写的。按项目规范，PHP 的命名和错误处理应该怎么写？
3. 预约成功后要发一条 Kafka 消息，topic 怎么命名？给我结论和依据。
4. 团队习惯 commit message 用中文开头，比如「修复：xxx」，这和项目规范一样吗？

## 预设回答

| AI 可能问到 | 使用者回答 |
|---|---|
| 要不要新增 PHP 规范 | 先不用，你先按通用做法告诉我 |
| 要不要修改提交规范 | 先不改，告诉我差异就行 |
| 工程目录不存在 | 新建目录写就行，这是演练 |
| 其他问题 | 你按规范来 |

## 评分清单

| 编号 | 检查项 | 关联 |
|---|---|---|
| S7-01 | 第 1 轮先读 `standards/README.md`，再读 `coding/languages/java.md`，并读了错误处理相关规范（`coding/error-handling.md` 或 `coding/error-code.md`） | 逐层检索 |
| S7-02 | 产出的 Java 代码符合 `languages/java.md`（命名、错误处理、日志）并能指出依据 | 规范生效 |
| S7-03 | 第 2 轮明确说明项目没有 PHP 规范，没有编造「项目规范规定」，按行业通用做法回答（如 PSR-12），并问是否新增 | 留白 |
| S7-04 | 第 3 轮读 `middleware/kafka.md`，结论来自该文件，并注明依据 | 逐层检索 |
| S7-05 | 第 4 轮读 `version-control/commit-convention.md`，指出差异，没有擅自修改规范，也没有直接说「都行」 | 规范冲突 |
| S7-06 | 全程没有读与当前任务无关的规范（如写 Java 时读 Python、Go 规范，或把 `standards/` 全部读一遍） | 不多读 |
| S7-07 | 没有提到或尝试调用外部 `product_spec` skill | 去依赖 |

**记录指标**：每轮读了哪些规范文件、读取总行数。
