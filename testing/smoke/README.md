## 启用时要做

- [ ] 填写下方「工程信息」和「用例清单」

- [ ] 在 `engineering/docs/ops-profile.md` 写明冒烟在流水线哪一步、失败时流水线怎么处理

---

## 规则

1. **跳过的用例不是通过**：结果写「通过 N / 失败 N / 跳过 N」，有跳过就写明跳过哪条、为什么、哪段功能因此没被验证。不能把「7 通过 1 跳过」写成「冒烟通过」
2. **冒烟只证明它跑过的路径**：可以作为 release.md「生产业务验证」中对应路径的证据，没覆盖到的业务路径仍要单独验证；冒烟不替代测试用例
3. **用例要写失败含义**：每条用例写明失败说明什么坏了，失败时据此判断回不回滚
4. **改冒烟用的变量、账号、触发方式**（如流水线变量、测试账号）属于运维变更，按 SOP-13 处理
5. **冒烟写入的数据**（造的订单、账号）写明怎么清理，生产上跑的冒烟按 [collaboration.md](../../agents/collaboration.md) §2 先取得授权
