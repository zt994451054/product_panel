## 规则

1. **跳过的用例不是通过**：结果写「通过 N / 失败 N / 跳过 N」，有跳过就写明跳过哪条、为什么、哪段功能因此没被验证。不能把「7 通过 1 跳过」写成「冒烟通过」。使用者决定接受未验证的风险时，原话记入版本 `decisions.md`，结果仍写跳过
2. **冒烟只证明它跑过的路径**：在生产上对本次发布的制品跑过的冒烟，可以作为 release.md「生产业务验证」中对应路径的证据；测试环境的冒烟结果不算生产证据。没覆盖的路径单独验证；冒烟不替代测试用例
3. **用例要写失败含义**：每条用例写明失败说明什么坏了，据此判断能不能进入测试、要不要回滚
4. **改冒烟的触发方式或流水线步骤**属于运维变更，按 SOP-13 处理；补配或更换变量、测试账号，经使用者同意后改，记在「工程信息」，并在测试环境跑一次留结果
5. **结果记在用它做判断的文档里**，本文件只放工程信息和用例清单，不记运行日志：进入测试记 `test-plan.md`「进入条件」；发布记 release.md；运维变更记 `ops-changes.md` 对应条目；因缺变量、账号而跳过的，作为待办记入当前版本 `test-plan.md`「执行就绪」表；其他时候只在回复里按规则 1 的格式说明
6. **冒烟写入的数据**（造的订单、账号）写明怎么清理；生产上跑的冒烟按 [collaboration.md](../../agents/collaboration.md) §2 先取得授权
